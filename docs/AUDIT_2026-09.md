### 3.1 Комбинаторный взрыв воркеров и сервисов
Каждая комбинация опций публикации (time/views × pin × forward × repeat) — отдельный модуль:

```

workers/publication_autodelete_views_pin.py
workers/publication_autodelete_views_pin_forward.py
workers/canonical_repeat_time_autodelete.py
workers/canonical_repeat_time_forward_autodelete.py
workers/canonical_repeat_time_pin_autodelete.py
workers/canonical_repeat_time_pin_forward_autodelete.py
services/canonical_publication_linked_repeat_time_pin_forward_parity.py
...
```

Целевая модель:
- [ ] Одна модель `Publication` с `PublicationOptions` (pin, forward_to[], autodelete: {kind: time|views, value}, repeat, silent, protect_content) — данные, а не ветки кода.
- [ ] Один `DeliveryWorker`: `plan = build_plan(publication)` → список шагов `[Send, Pin, Forward, ScheduleAutodelete, ScheduleRepeat]`. Каждый шаг — маленький класс с идемпотентностью (по `publication_id + step_name`). Новые опции добавляются как шаги, а не как новые файлы.
- [ ] Удалить 8 комбинаторных воркеров и все `*_parity`, `*_shadow`, `*_verifier`, `*_authority` сервисы после переноса логики.

### 3.2 Двойственность Legacy `PostTask` ↔ Canonical `Publication`

## 4. Studio (Telegram Mini App)

### 4.1 Факты
- React 18 + Vite + Tiptap + `@tma.js/sdk-react`.
- Установлен `@telegram-apps/telegram-ui` (и его CSS), но используется **один компонент — `AppRoot`**.
- 16 рукописных CSS-файлов, 1393 строки, классы `.button.primary`, `.panel`, `.nav-item`; 7 разных брейкпоинтов (480/620/720/900/980/1050/1180).
- Раскладка desktop-first: сайдбар 238px; на `<720px` — горизонтальная лента, шрифт кнопок до 11px, ни одного `min-height: 44px`.
- Studio не открывается из бота: в Python нет `MenuButtonWebApp` / `WebAppInfo`.

### 4.2 Решение по coss.com/ui — НЕ брать как основу
coss/ui — shadcn-подобный набор на Base UI + Tailwind для обычных веб-приложений. Для Mini App проигрывает:
1. Пользователь ожидает нативный вид Telegram: цвета из `themeParams` (`--tg-theme-*`), `MainButton`/`SecondaryButton`/`BackButton`, автоматическая тёмная тема. coss/ui придётся перекрашивать под ~20 переменных Telegram.
2. Tailwind + Base UI — второй UI-фреймворк рядом с уже установленным `@telegram-apps/telegram-ui`, сделанным специально под TMA.
3. Base UI не mobile-first; для админки с телефона риски выше выгоды.

Из coss/ui брать только **паттерны** (Command-палитра, Drawer со snap-points, Empty-состояния, Toast) и реализовывать через telegram-ui / нативные `showPopup`.

### 4.3 План
- [ ] Реально использовать `@telegram-apps/telegram-ui`: `Button`, `Section`, `Cell`, `List`, `Tabbar`, `Modal`, `Snackbar`, `Input`, `Placeholder` вместо самописных `.button`, `.panel`, `.nav-item`.
- [ ] Свести 16 CSS-файлов в `tokens.css` (spacing/radius/typography на базе `--tg-theme-*`) + CSS-модули по компонентам; один набор брейкпоинтов: `sm 480 / md 768 / lg 1024`.
- [ ] Mobile-first: нижний `Tabbar` (Контент / Источники / Инбокс / План / AI); сайдбар — только `≥1024px`.
- [ ] Тач-цели ≥44px; шрифт всех инпутов ≥16px (иначе iOS Safari зумит); `viewport` с `maximum-scale=1`.
- [ ] Вход из бота: `set_chat_menu_button(MenuButtonWebApp)` при `/start`; `WebAppInfo`-кнопки в контент-плане с deep-link `?startapp=content_<id>`.
- [ ] `addToHomeScreen` для админов; `CloudStorage` для синка черновиков между устройствами (сейчас только `DeviceStorage`); `SettingsButton` → настройки канала.
- [ ] Bot API 10.2: с 20.07.2026 методы Mini App блокируются с origin, не зарегистрированного в BotFather. Убедиться, что Studio раздаётся строго с зарегистрированного домена (сейчас vite-proxy на `127.0.0.1:8080`).
