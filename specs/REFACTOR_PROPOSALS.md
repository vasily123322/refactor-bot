## Предложения по рефакторингу

### 1) Чёткие границы сервиса LLM
- В `AIGenerationService` развести ответственность:
  - Выделить адаптер `OpenRouterClient` (формирование payload, вызовы API, обработка ошибок/повторов)
  - Выделить `PromptBuilder` со стратегиями: `from_scratch`, `from_link`, `improve`
  - Хранить побочные уведомления (80% квоты, сообщения в админ-канал) за интерфейсом `Notifier`
- Эффект: тестируемость, изоляция сети, упрощение мока при юнит-тестах

### 2) Повторы и устойчивость сети
- Добавить экспоненциальный backoff и ограничение повторов для HTTP (обёртка вокруг httpx)
- Именованные таймауты и общие константы в `core/config`
- Логирование корелляционных ID для запросов

### 3) Типизация и контракты
- Аннотации возвращаемых структур (`TypedDict`/`dataclass`) для ответов сервиса LLM
- В репозиториях — точные типы полей и возвратов; избегать `Any`

### 4) Конфигурация
- Валидировать `settings.ai_models_json` при старте (schema + ошибки в лог)
- Явные флаги для нотификаций (вкл/выкл 80% уведомлений)

### 5) Упрощение больших методов
- Разбить длинные методы `generate_from_link`/`generate_text` на этапы: валидация → подготовка → вызов → пост-обработка
- Вынести парсинг HTML в `services/extractors/html.py`

### 6) Тестопригодность
- Интерфейсы `Clock`/`UUID`/`Now` для детерминированности
- Фейковый `OpenRouterClient` и in-memory репозитории для тестов

### 7) Безопасность и устойчивость БД
- Ограничения на длину текстов при записи (sanitization)
- Механизм «простых миграций» вынести из `db.py` в `scripts/migrations`

### 8) Телеграм-нотификации
- Абстрагировать отправку через `Notifier`, чтобы отключать в сборках без бота
- Кнопки/тексты — шаблоны в ресурсах, без inline-строк

### 9) Слои и зависимости
- Правило: `bot/ui` → `services` → `repositories` → `domain`/`core`
- Запрет обратных ссылок (контроль import-linter)

### 10) Наблюдаемость
- Middleware логирования запросов LLM (время/токены/модель/ошибки)
- Метрики (Prometheus): генерации, ошибки, квоты, токены
