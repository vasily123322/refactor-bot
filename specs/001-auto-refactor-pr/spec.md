# Feature Specification: Auto-Refactor Pull Requests

**Feature Branch**: `001-auto-refactor-pr`
**Created**: 2025-10-28
**Status**: Draft

## Summary
Автоматический бот открывает безопасные PR с минимальными, изолированными улучшениями качества кода
(стиль, типизация, мёртвый код, микровыигрыши производительности), строго сохраняя поведение.

## Goals
- Повышать читаемость и поддерживаемость без изменения бизнес‑логики.
- Соблюдать локальные соглашения проекта и существующее форматирование.
- Минимизировать шум: править только действительно необходимые строки.
- Обеспечить «зелёный» CI: все линтеры/тесты проходят после правок.

## Non‑Goals
- Большие/архитектурные рефакторинги и изменения поведения.
- Обновления зависимостей, миграции БД, генерация API.
- Массовые форматирования «всего репо».

## User Stories
1. Как разработчик, хочу получать PR с мелкими улучшениями (именование, явные импорты,
   удаление неиспользуемого кода), чтобы ускорить ревью и снизить технический долг.
2. Как мейнтейнер, хочу чтобы каждый PR содержал чёткую сводку изменений, ссылки на правила,
   и всегда проходил существующие проверки CI без ручных фиксов.
3. Как ревьюер, хочу, чтобы дифф был минимальным и не затрагивал несвязанные строчки; комментарии
   и стилистика проекта оставались прежними.
4. Как владелец репозитория, хочу конфигурировать набор правил/порогов и расписание запуска,
   чтобы контролировать объём и частоту PR.

## Acceptance Criteria
- PR заголовок формата: `chore(refactor-bot): <summary>`; тело PR включает:
  - перечень категорий изменений (стиль/типизация/мёртвый код/микро‑perf),
  - подтверждение отсутствия изменения поведения,
  - результаты локальных проверок (линтеры/тесты) и ссылки на логи.
- Все существующие CI‑джобы проходят без дополнительных правок.
- Порог шума: изменённых строк ≤ целевого лимита (по умолчанию 150), файлов ≤ 15.
- Не добавляет новые зависимости/скрипты; не трогает конфиг форматтера без согласования.
- Сохраняет комментарии, лицензии и заголовки файлов; не удаляет явные инварианты.
- Для каждой категории изменений указана мотивация (например, «неиспользуемый импорт»).

## Constraints & Principles
- Следовать `.specify/memory/constitution.md`.
- Если есть `project-specs.md` — отражать новые соглашения перед внедрением.
- Не трогать бинарники, сгенерированные файлы, миграции и снапшоты тестов без явной причины.

## Configuration
- Файл конфига: `.specify/refactor-bot.yaml` (по умолчанию создаётся с безопасными настройками).
  - thresholds: `maxChangedLines: 150`, `maxFiles: 15`
  - categories: `style`, `typing`, `dead_code`, `micro_perf`
  - exclude: `[**/venv/**,**/.venv/**,**/node_modules/**,**/.specify/**,**/.cursor/**,**/alembic/**,**/*.min.*]`
  - ci: `preCheck: "uv run ruff check && uv run pytest -q"` (пример)

## Dependencies
- Требует существующей CI‑конфигурации (линтеры/тесты). Новые зависимости не добавляются.

## Risks & Mitigations
- Ложноположительные изменения поведения → Митигация: запускаем тесты и ограничиваем охват, маленькие PR.
- Конфликты с активными ветками → Митигация: маленькие батчи, частый запуск, авто‑ребейз при необходимости.

## Metrics
- Merge rate автоматических PR ≥ 80%.
- Среднее время ревью < 24h.
- Снижение предупреждений линтера на затронутых модулях на ≥ 20% за месяц.

## Rollback
- Отклонить/закрыть PR; изменений в main ветке не остаётся.
