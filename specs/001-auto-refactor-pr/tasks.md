# Tasks: Auto-Refactor Pull Requests

## Phase 1 — Bootstrap
1. [P] Создать `.specify/refactor-bot.yaml` с безопасными порогами и exclude.
2. [P] Убедиться, что `.cursor/` и чувствительные артефакты в `.gitignore`.
3. [P] Проверить доступность `uv`, `ruff` и тестового раннера (pytest) локально/в CI.

## Phase 2 — Static Analysis
4. [P] Собрать список файлов‑кандидатов, исключая `venv/.venv/node_modules/.specify/.cursor/alembic/*` и бинарники.
5. [ ] Найти неиспользуемые импорты/переменные и мёртвые функции по кандидатам.
6. [ ] Детектировать безопасные подсказки типизации (где нет изменения контрактов).
7. [ ] Обнаружить микро‑perf замены без изменения поведения (локальные, очевидные).

## Phase 3 — Apply Small Batches
8. [ ] Сформировать батч ≤150 строк и ≤15 файлов; применить только нужные строки.
9. [ ] Сохранить комментарии/лицензии/заголовки; не трогать форматтер/конфиги.

## Phase 4 — Pre‑Check & PR
10. [ ] Запустить `ci.preCheck` (линтеры/тесты). При провале — уменьшить батч.
11. [ ] Сформировать PR: заголовок `chore(refactor-bot): <summary>`, тело: категории, подтверждение отсутствия изменения поведения, логи.

## Phase 5 — Iterate
12. [ ] Повторить для следующих батчей, пока есть кандидаты; следить за конфликтами.

## Files & Paths
- `.specify/refactor-bot.yaml` — конфиг порогов/категорий/исключений/команд.
- `specs/001-auto-refactor-pr/*` — артефакты спеки/плана/тасков.

## Checkpoints
- После шага 3 — готовы инструменты и конфиг.
- После шага 11 — первый PR готов, CI зелёный.
